# OpenReactions

A browser-based tool for drawing chemical structures and reaction schemes, live at
**[openreactions.com](https://openreactions.com)**. Draw molecules and full
equations, label atoms, add reagents and conditions, and export a clean image —
no install, no account required.

Built by Nathan Levy (PO '27). The goal is ChemDraw-quality output with
Marvin-like ease of use.

---

## Repo layout

```
index.html              the drawings dashboard — plain HTML/CSS/JS, no build step
supabase-config.js      backend keys, read at runtime by BOTH the homepage and the app
vendor/supabase.js      Supabase client for the homepage (vendored, no CDN)
draw/                   the drawing app — React 19 + Vite, served at /draw/
deploy/                 build output that gets published (gitignored)
docs/                   feature roadmap
plan.md                 running improvement log / status
SUPABASE_SETUP.md       one-time backend setup walkthrough
```

Two independent pieces published to one domain: `/` is a static page, `/draw/` is
the React app. They share a Supabase session automatically (same origin), which is
why signing in on the homepage also signs you in to the editor.

## Running locally

```sh
(cd draw && npm install)   # once
npm run dev                # from the repo root -> http://localhost:5173/draw/
```

To work on the homepage, serve the repo root over HTTP — opening `index.html` as a
`file://` URL means `/supabase-config.js` won't resolve and accounts appear to be
switched off:

```sh
python3 -m http.server 8000    # from the repo root -> http://localhost:8000/
```

To test the exact thing that gets published, build and serve `deploy/`:

```sh
npm run predeploy
cd deploy && python3 -m http.server 8088
```

## Deploying

Manual — there's no CI.

```sh
npm run predeploy    # vite build + copy everything into deploy/
npm run deploy       # gh-pages pushes deploy/ to the gh-pages branch
```

**Before deploying**, make sure git is using the account that owns the repo. Git
delegates GitHub credentials to `gh`, and this machine has two accounts logged in:

```sh
gh auth switch --user natelevy2468
```

Without this the push fails with
`Permission to natelevy2468/openreactions.git denied to natelevy2468-star`.

GitHub Pages takes ~1 minute to serve the new build. `CNAME` and `.nojekyll` are
generated by `predeploy`.

## Accounts and saving

Modelled on Google Docs: **there is no save button.** Drawings save themselves,
survive reloads, and are listed on the homepage.

**Two layers, because they fail differently:**

1. **Local storage**, written on every edit. This is the crash net — reloading,
   closing the tab, or losing the network never loses work — and it's the *only*
   layer when nobody is signed in.
2. **Supabase**, written on a ~1.2 s debounce, so drawings follow you between
   devices and show up on the homepage.

**Rules worth knowing before changing this code:**

- A database row is created **lazily**, on the first edit that leaves the canvas
  non-empty — opening the editor and leaving doesn't create empty "Untitled" rows.
- Panning and zooming are saved but never trigger a network write on their own
  (`contentFingerprint` deliberately excludes the view).
- On load, whichever copy is newer wins — but only if the content actually
  differs, so re-opening a document doesn't bump it to the top of "recent".
- `?doc=<uuid>` is a document's address. `?new=1` forces a blank one (that's what
  the homepage's "New drawing" button links to).
- Signing out keeps the drawing on screen and remembers which document it is, so
  signing back in **resumes** it rather than cloning it.
- If a save fails, the header says so and the work stays local; it gets pushed on
  the next successful load.

**What the user sees:** an editable document name plus a live save status in the
editor's header, a **My drawings** dropdown (switch / rename / duplicate / delete
/ new), an account menu, and a homepage **Drawings** dashboard. The dashboard
loads the full cloud library in pages, with name search, sorting, and grid/list
views. Product information and instructions live in a separate **About & help**
section. Signed-out users see their browser draft.

### Backend

One Supabase project: a single `drawings` table with row-level security so a user
can only ever touch their own rows, and a trigger that owns `updated_at` and
refuses attempts to change a row's owner. Full setup (with the SQL, and
step-by-step Google sign-in instructions) is in
**[SUPABASE_SETUP.md](SUPABASE_SETUP.md)**.

Keys live **only** in `supabase-config.js` at the repo root — one file, read at
runtime by both halves of the site, so there's nothing to rebuild after changing
them. The anon key is meant to be public; RLS is what protects the data. Never put
the `service_role` key there.

Leaving that file blank is a supported state: the app still works completely,
keeps drawings in the browser. The homepage keeps sign-in visible and explains when accounts are unavailable; the editor hides account controls when no backend is configured.

Google sign-in **auto-detects** — the app asks the project which providers are
enabled, so switching Google on in the Supabase dashboard makes the button appear
with no code change and no redeploy, and it can never show up unconfigured.

## What the drawing tool does

- **Draw** by clicking to place an atom then clicking a grey suggestion ghost to
  extend at 60° angles; click a bond to cycle single → double → triple.
- **Templates**: benzene, cyclohexane/pentane/butane/propane, chair, Newman.
- **Atom labels** by hovering a vertex and typing (implicit hydrogens are worked
  out for you), including **abbreviation groups** — `Ph`, `Bn`, `OMe`, `OAc`,
  `CO₂Me`, `NO₂`, `CF₃`, `tBu`, `Ts`, `Boc`, `TMS`… which display as the
  abbreviation but expand chemically for formula and SMILES.
- **Reaction schemes**: forward, equilibrium and six curved arrows; reagents above
  and conditions below an arrow (double-click it); `+` separators between
  reactants (place one with the text tool — it has no button of its own yet).
- **Stereochemistry**: wedge, dash and ambiguous bonds. Charges and lone pairs.
- **Info panel**: molecular formula, molecular weight, monoisotopic mass, heavy
  atom count, ring count.
- **SMILES in and out**, from the settings dropdown. Dark mode lives there too.
- **Zoom / pan**: the `− 100% +` pill (middle button = fit to content), wheel to
  pan, ⌘/Ctrl+wheel to zoom toward the cursor.
- **Export** a cropped, high-resolution PNG, or copy it to the clipboard.

Keyboard: `D` draw, `E` erase, `M`/`Esc` select, `T` text, `A` arrow, `Q`
equilibrium, `R` benzene, `3`–`6` rings, `G`/`J` charge ±, `L` lone pair, `⌘Z` /
`⇧⌘Z` undo/redo, `⌫` delete selection, `⌘S` save now. The letters are all
non-element symbols, so they can never be confused with typing an atom label.

## Code map

The drawing app is still dominated by one large file, but the pieces that could
be pulled out have been:

| Path | What's in it |
| --- | --- |
| `draw/src/HexGridWithToolbar.jsx` | ~5.9k lines: all canvas state, `drawCanvas`, `handleCanvasClick`, the header |
| `draw/src/components/` | Presentational UI — tool palette, popups, auth dialog, drawings panel, document title |
| `draw/src/hooks/useDocumentSync.js` | The autosave engine (see "Accounts and saving" above) |
| `draw/src/hooks/useAuth.js` | Session state + auth actions, with human-readable error messages |
| `draw/src/lib/` | Supabase client, `drawings` CRUD, local-storage mirror, document shape |
| `draw/src/rendering/` | Bond/arrow/text/lone-pair/stereo drawing, ring detection |
| `draw/src/utils/` | Geometry, hit testing, snapping, valence, vertex merging, export cropping |
| `draw/src/chemistry/` | OpenChemLib bridge: SMILES import/export, formula, abbreviations |

The **data model is geometric, not chemical**: `vertices` are `{x, y}` points,
`segments` are bonds with a `bondOrder`, `vertexAtoms` maps a vertex to its label.
There's no valence graph of its own — OpenChemLib is used on demand for formula
and SMILES.

## Gotchas for future work

Things that have already cost time:

- **Renderers that key off topology must use untrimmed bond geometry.** Bonds are
  clipped back so they don't run through atom labels; a ring-membership lookup
  that compares *clipped* coordinates against stored full-length ones silently
  fails. `renderDoubleBondByCase` takes a separate `geomBond` for exactly this.
- **Temporal dead zone risk.** Many `const x = useCallback` are referenced by
  earlier callbacks through dependency arrays; adding a dep on a later-defined
  callback crashes the whole render.
- **Absolutely-positioned overlays** (atom input, arrow-label editor) live in the
  root fixed div, but the canvas starts at x≈240, y≈50 because of the toolbar.
  Store viewport coordinates, and multiply by `scale` when zoomed.
- **The Vite dev server can serve a stale broken module** after several rapid
  saves — a blank white screen or a TDZ error that isn't in the current source.
  Restart it before believing a blank render.
- **`eslint` flags `React` as unused** in every JSX component here. It's a false
  positive from the old-style import the codebase uses; the build is the source of
  truth.
- **`draw/node_modules` is tracked in git** (committed before `.gitignore`
  existed). Harmless, but it makes `git status` noisy — filter it out.
- **Runtime configuration is served in development at both** `/supabase-config.js`
  and `/draw/supabase-config.js`. The production site serves the root file directly.

## Testing

Run the production build and browser regression suite:

```sh
npm run build
cd draw
npm run test:chemistry
npm run test:browser
```

The suite starts a temporary local server and headless Chrome. On macOS it uses
Google Chrome from Applications; elsewhere set `CHROME_PATH` to the Chrome binary.
It requires Node 20 or newer and permission to open local ports and launch Chrome.

It covers homepage sign-in visibility on desktop and mobile, opening/dismissing
the auth dialog, a 105-document library fixture (pagination, search, sorting,
grid/list views, and About navigation), local recovery after a failed cloud load, switching documents
while cloud creation or updates are pending, and deleting without re-saving.
It also drives the production editor to draw benzene, rename, reload, and export
a PNG and a vector SVG, and exercise structure cleanup. Chemistry unit tests
check stereochemistry, isotope/radical exchange, layout, reflection, validation,
MOL/SDF/RXN exchange, and abbreviation contraction. Persistence tests use a controlled backend; they do not modify real
Supabase accounts or drawings. Screenshots are written to a temporary directory
printed at the end of the run.

Real Google OAuth, email delivery, and cross-device account sync still require
an end-to-end check with a configured test account.

## Chemistry editing additions

The editor now includes structure cleanup, selection rotation and reflection,
reaction alignment and spacing, common-element shortcuts, plus signs, resonance
arrows, and duplication of a selected structure as a product. Open **Tools** in the top bar for SMILES/MOL/SDF/RXN import and export, basic chemistry checks,
saved fragments, abbreviation expansion/contraction, drawing styles, vector SVG,
and browser print/save as PDF. Geometry changes participate in undo/redo.

Chemical exchange preserves tested tetrahedral and double-bond stereochemistry,
isotopes, and radicals. Abbreviation contraction verifies chemical identity before
replacing a selected fragment. RXN exchange supports a single reaction arrow;
imports containing agents are rejected explicitly. Layout and selection transforms
have separate restrictions for Newman projections. Chemistry checks detect common
valence problems and are not a comprehensive chemical validity guarantee.

Browser recovery includes independent local drawings, up to 20 local checkpoints,
and locally recoverable copies of cloud drawings deleted through the editor.
These recovery records are device-local, not shared cloud version history or
server-side trash. Storage failures are surfaced instead of reporting a successful
save. Real-account OAuth and cross-device sync still need manual verification.

Remaining advanced gaps include atom mapping, multistep reaction semantics,
collaborative editing, cloud version history, folders, and access-controlled sharing.
